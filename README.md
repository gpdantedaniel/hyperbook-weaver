# The Hyperbook Weaver 🕷️

The Hyperbook Weaver is a topic modeling pipeline designed to semantically link all the papers found in the [Hyperbook](https://bioengineering.hyperbook.mcgill.ca/), a website maintained by McGill University's [Bioengineering Department](https://www.mcgill.ca/bioengineering/) that hosts papers written by students from the course [BIEN 200](https://coursecatalogue.mcgill.ca/courses/bien-200/index.html). Using embeddings generated by LLMs, it links papers by clustering keywords together and finding common topics across papers. This paper nonetheless works with any kind of collection of objects with natural language descriptions.

This project was developed by [Dante Garcia](https://www.linkedin.com/).

## Application Setup

Running the application by yourself is easy, but it takes a bit of setup work. You can follow these steps below to accomplish this:

### 1. 🧠 Setting up [Azure OpenAI](https://azure.microsoft.com/en-us/products/ai-services/openai-service) (Optional)

OpenAI's models can be used for embedding your articles and naming topics based on their most relevant keywords. To deploy your own models, you can follow this guide on [deploying your models on Azure AI Foundry](https://learn.microsoft.com/en-us/azure/ai-foundry/how-to/deploy-models-openai). 

If you choose to deploy OpenAI models with Azure, will need to deploy at least text-emebdding-3-large and gpt-4o. You must take note of their endpoint, their API version and their API key. Note these values down somewhere secretly. Here are some examples of values:

```
AZURE_OPENAI_API_KEY=a123456b_super_secret_key
AZURE_OPENAI_API_VERSION=2024-10-21
AZURE_OPENAI_ENDPOINT=https://your-resource.openai.azure.com/
```

### 2. 🤗 Setting up [HuggingFace Dedicated Endpoints](https://huggingface.co/inference-endpoints/dedicated) 

If you don't have a powerful GPU with at least 16 GB of VRAM, you can use HuggingFace inference endpoints by deploying your own models online. To do so, you must create an account with HuggingFace, and then create a token folllowing these [instruction](https://huggingface.co/docs/hub/en/security-tokens). Write it down somewhere secretly as follows:

```
HF_TOKEN=hf_super_secret
```


You can deploy your models [using this link](https://endpoints.huggingface.co/catalog). If you do, make note of the generated endpoint and store it somewhere:

```
HF_ENDPOINT=https://ssomething.endpoints.huggingface.cloud
```

We recommend that you deploy either of these models listed in ascending order of cost:

```
Qwen/Qwen3-Embedding-0.6B
Qwen/Qwen3-Embedding-4B
Qwen/Qwen3-Embedding-8B
```

### 4. 🦙 Installing [Ollama](https://ollama.com/)

If you do happen to have a very powerful GPU, you can run your own models on your computer! Ollama is a useful application that allows you to run models locally. You can [download it here](https://ollama.com/download).

Once that is downloaded, you can install the models using the command prompt or the terminal on your computer. For windows, search and open CMD, and then run these commands individually to download these models that we recommend:

```
ollama pull hf.co/Qwen/Qwen3-Embedding-0.6B-GGUF:F16
ollama pull hf.co/Qwen/Qwen3-Embedding-4B-GGUF:F16
ollama pull hf.co/Qwen/Qwen3-Embedding-8B-GGUF:F16
```

### 5. 🐳 Installing [Docker Desktop](https://docs.docker.com/desktop/)

The application can be run as a Docker container on your own computer. To run Docker containers however, you must first install [Docker Desktop](https://docs.docker.com/desktop/). Once it's installed, just click on the app to get it up and running.

### 6. 📦 Runing the Application as a Docker Container

Once Docker Desktop is running on your computer, download the container using the following command:

```
docker pull dantegp/personal:hyperbook-weaver
```

Assuming that the download worked, you can then run it yourself using this command. Don't forget to replace the placeholder values in this command that you noted down earlier!

```
docker run ^
-p 7860:7860 ^
-e HF_TOKEN=hf_super_secret ^
-e HF_ENDPOINT=your_endpoint ^
-e AZURE_OPENAI_API_KEY=your_key ^
-e AZURE_OPENAI_API_VERSION=your_api_version ^
-e AZURE_OPENAI_ENDPOINT=your_azure_openai_endpoint ^
dantegp/personal:hyperbook-weaver
```

## Updating a Cloud ChromaDB Database (for the VR Museum Project)

If you have a ChromaDB database that is running online as a semantic search knowledge base, you can also use this application to reindex the contents of your database. This involves doing the following:

### 1. Getting your ChromaDB credentials

Once you [create an account](https://www.trychroma.com/) and make a database of our own, you will be shown an API key, a tenant ID and the name of the database you made. Take note of these and write them down somewhere secretly.

```
VRMUSEUM_CHROMA_API_KEY=your_key
VRMUSEUM_CHROMA_TENANT=your_tenant_id
VRMUSEUM_CHROMA_DATABASE=your_database_name
```

Within a database that you make, you may create collections. For whichever collection you make, take note of its name and store it as follows:

```
VRMUSEUM_CHROMA_COLLECTION=collection_name
```

With these in hand, you just have to amend the run function above and replace the placeholders by all the values that you have noted down:

```
docker run ^
-p 7860:7860 ^
-e HF_TOKEN=hf_super_secret ^
-e HF_ENDPOINT=your_endpoint ^
-e AZURE_OPENAI_API_KEY=your_key ^
-e AZURE_OPENAI_API_VERSION=your_api_version ^
-e AZURE_OPENAI_ENDPOINT=your_azure_openai_endpoint ^
-e VRMUSEUM_CHROMA_API_KEY=your_key ^
-e VRMUSEUM_CHROMA_TENANT=your_tenant_id ^
-e VRMUSEUM_CHROMA_DATABASE=your_database_name ^
-e VRMUSEUM_CHROMA_COLLECTION=collection_name ^
dantegp/personal:hyperbook-weaver
```
